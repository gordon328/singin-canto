# 唱学粤语 · 设计规范（「丁香」风格）

> 给 Claude Code：这是开发者和 Claude（claude.ai）一起定下的视觉设计。开发者在设计画布上从三个方向里选了「丁香」（C 方向），并确认了学习流程和校对歌词的画面。**所有页面（包括以后新做的）都按这份规范做。** 开发者会把设计画面的截图放在 `docs/design/` 里，做页面时对照截图。

## 1. 设计目标

开发者对旧界面的意见（原话的意思）：
- 喜欢简洁，但旧界面"很 bland"，缺少"让眼睛觉得舒适"的感觉
- 字体不统一（旧版混用了宋体、黑体、等宽字体）
- 歌曲卡片没有和上面对齐
- 完全没有过渡动画，按钮按下去没有反馈

所以新设计的原则：
1. **一种中文字体**：所有汉字（标题、歌词、按钮、说明）都用系统苹方
2. **柔和**：浅紫调的底色，卡片用很淡的阴影区分，不用边框；圆角大
3. **有手感**：每个可以点的东西，按下去都有反馈；页面切换有过渡
4. **对齐**：所有内容用同一套左右边距

## 3. 字体

### 3.1 字体族

```css
--font-cjk: -apple-system, "PingFang HK", "PingFang SC", "Noto Sans CJK TC", "Microsoft JhengHei", sans-serif;
--font-latin: "Outfit", var(--font-cjk);
```

- **所有中文**：`--font-cjk`（iPhone 上就是苹方）。**不再使用宋体（Noto Serif HK）和等宽字体（JetBrains Mono）**
- **粤拼、数字、时间、倍速**：`--font-latin`（Outfit，圆润的英文字体）
- Outfit 用 500 / 600 / 700 三个字重

⚠️ **Outfit 字体文件要放在项目里**（`fonts/` 文件夹，woff2 格式，Outfit 是 OFL 开源授权，可以自带），不要从 Google Fonts 加载。原因：Google 的服务在中国大陆打不开，以后分享给大陆朋友会加载失败；而且自带字体才能离线使用。

### 3.2 字号

| 用途 | 字号 | 字重 |
|---|---|---|
| 首页标题「唱学粤语」 | 30px | 700 |
| 完成页标题 | 26px | 700 |
| 页面标题（顶部栏） | 16–17px | 700 |
| 卡片标题、歌名 | 17px | 600 |
| 正文、按钮 | 15–16px | 600（按钮）/ 400（正文） |
| 说明、提示 | 14px | 400，行高 1.6 |

## 4. 间距、圆角、阴影

### 4.1 间距

- **页面左右边距：16px**（首页 20px）。所有卡片、列表、按钮都对齐这条边
- 卡片之间：10–12px
- 区块之间：22px
- 卡片内边距：12–20px

⚠️ 所有设了 `width: 100%` 又有 `padding` 的元素，必须加 `box-sizing: border-box`。旧版歌曲卡片超出右边，就是缺了这个。**建议全局加 `*, *::before, *::after { box-sizing: border-box; }`**

### 4.2 圆角

| 元素 | 圆角 |
|---|---|
| 小按钮、输入框 | 12–14px |
| 普通按钮、图标按钮 | 16–18px |
| 声调键帽、歌曲首字方块 | 18px |
| 列表卡片、歌曲卡片 | 22px |
| 大卡片（今天的学习、学词卡片） | 28–30px |
| 底部弹出层 | 顶部 34px |
| 浮动播放条 | 30px |

### 4.3 阴影

只用三档，不要加边框：
```css
--shadow-1: 0 2px 10px rgba(34,31,51,.05);   /* 普通卡片 */
--shadow-2: 0 10px 30px rgba(34,31,51,.08);  /* 学词卡片等主要卡片 */
--shadow-3: 0 12px 34px rgba(34,31,51,.12);  /* 浮动播放条、悬浮按钮 */
```
深色模式下阴影基本看不见，改用卡片底色（`--surface`）和页面底色（`--bg`）的明暗差来区分。

| 类型 | 样式 | 用在哪里 |
|---|---|---|
| 主要 | `--accent` 底，`--on-accent` 字 | 「开始今天的学习」「听标准发音」「保存」 |

**按下效果（所有按钮）**：按下时 `transform: scale(.97)`，底色变成对应的 press 色，时长 120ms。~~用 `:active` 实现~~ → **现在用 JS 加的 `.is-pressed` class 实现，不用 `:active`**（原因和规则见下面第二次修复）。会按下的元素统一写在代码的 `PRESSABLE` 选择器里（现在是 `.btn, .tones .key, .song, .ib, .res`），新做的可点元素要加进去；样式写成 `.xxx.is-pressed { … }`。

**（2026-10-27 M3 验收）** iPhone 上点完按钮切到别的页面再回来，按钮可能停在"按下"的样子。规则：
- `:hover` 样式只能写在 `@media (hover: hover)` 里（iPhone 没有鼠标，不会生效）
- ~~每次切换页面后，按下效果先关掉（body 加 `settling`）~~（第一次修复，真机上还会卡约 1 秒）
- **（2026-10-27 第二次修复）按下效果不用 CSS `:active`，改成 JS 控制**：手指按下（pointerdown）加 `.is-pressed`，抬起、取消、移出按钮、页面滚动时立刻去掉。会跳转页面的按钮：先去掉按下效果，等一帧让页面画出"松开"的样子再跳转（Safari 右滑返回时拍的快照也是松开的）。popstate 和 pageshow 时清掉所有 `.is-pressed`

**删除按钮**：「⋯」菜单里的删除用 `--danger` 字色；确认窗里的「删除」是 `--danger` 底、`--on-accent` 字。

### 5.2 声调键帽（首页六个声调）

像键盘上的实体键帽，由**两层**组成：
- **底座**：声调色，**固定不动**，平时只露出键面下方 4px，像键帽的"厚度"或阴影
- **键面**：白底（`--surface`），圆角 18px，汉字 22px 在上，粤拼 12px（声调色）在下
- **按下时**：只有键面往下移 4px，正好盖住底座；底座和整个按钮的位置都不动。键面底色变 `--surface-press`。时长 100ms；松开时弹回
- 点了朗读这个字

结构和样式（键帽总高 66px）：
```html
<button class="key" style="--tone: var(--t3)">
  <span class="key-base"></span>
  <span class="key-face"><span class="hz">富</span><span class="jp">fu3</span></span>
</button>
```
```css
.key { position: relative; height: 66px; padding: 0; border: 0; background: none; }
.key-base { position: absolute; left: 0; right: 0; top: 4px; bottom: 0;
            border-radius: 18px; background: var(--tone); }          /* 不动 */
.key-face { position: absolute; left: 0; right: 0; top: 0; bottom: 4px;
            border-radius: 18px; background: var(--surface);
            display: flex; flex-direction: column; align-items: center; justify-content: center;
            transition: transform 100ms var(--ease), background 100ms; }
.key.is-pressed .key-face { transform: translateY(4px); background: var(--surface-press); }
```
不要在 `.key` 本身上做 transform，也不要用 box-shadow 画彩色底边，否则底座会跟着键面一起移动。

标题行：「六个声调 · jau」（显示当前这组的音节），右边「换一组」浅色小按钮（带刷新图标）。换组时六个键帽依次淡出淡入（每个延迟 30ms）。

### 5.6 弹出层不使用暗幕

**2026-10-28 决定：整个 App 的弹出层（底部弹窗、下拉菜单）后面都不变暗，不用任何暗色遮罩。**
原因：Safari 里状态栏那一条由 Safari 自己画。网页想让它跟着变暗，要么有延迟、会闪（M3.6–M3.9），要么不闪但状态栏不变暗、和下面变暗的页面不协调（M3.11）。试验经过见 7.4。

底部弹出层（词卡、删除确认、未保存提示、词汇包等）：
- 从底部滑上来（`--dur-slow`），顶部圆角 34px，白底（`--surface`）
- 靠更明显的阴影浮在页面上：`--shadow-sheet`（`0 -8px 40px rgba(34,31,51,.18)` + 1px `--rule` 描边；深色模式阴影加深）
- **普通弹窗**（词卡、词汇包）：顶部有拖动条（40×5px，`--rule`），可以往下拖关闭，**点弹窗外面也关闭**。点外面这一下只用来关闭，不会顺便点到下面的字或按钮；手指在外面滑动（滚动页面）不算点
- **确认类弹窗**（删除确认、「有改动还没保存」）：没有拖动条，点外面、往下拖都不关，**必须点按钮**。所以每个确认类弹窗都要有一个"不做"的按钮（「取消」/「继续编辑」）
- 备份不用弹出层，在「设置」整页里（首页右上角齿轮，像歌曲页一样从右边滑入）
- 顶部附近不能出现有颜色的 fixed 元素（见 7.4）；底部弹窗贴着屏幕底部，没关系

### 5.9 下拉菜单（2026-10-28 新增）

用在歌曲页右上角「⋯」：
- 点「⋯」后在按钮**正下方**弹出（间隔 6px，右边和按钮对齐），最小宽 200px
- 白底（`--surface`），圆角 16px，阴影 `--shadow-menu`（浅色 = `--shadow-3`；深色加 1px `--rule` 描边），里边距 6px
- 每一项是左对齐的文字按钮，至少 48px 高，圆角 12px，按下时底色 `--surface-press`（不缩放）
- 菜单项：「编辑歌曲」「词汇包」（已导入时显示「词汇包 ✓」）「删除」。删除用 `--danger` 红字，点了先弹删除确认（5.6 确认类弹窗）
- 动画：从按钮位置（右上角）由 0.92 倍缩放到 1 倍并淡入，180ms
- **背景不变暗**。点菜单外面或再点「⋯」就关闭；点外面这一下不会点到下面的东西。切页时直接收起
- 实现：菜单放在吸顶顶栏 `.bar` 里，`position: absolute`（**不是 fixed**，见 7.4：顶部附近不能有带颜色的 fixed 元素），页面滚动时跟着顶栏

### 5.10 首页选择模式和撤销提示条（2026-10-27 新增，功能见开发规格 7.4）

- 「我的歌」标题右边：文字小按钮「选择」（没有歌时不显示）
- 选择模式：
  - 每张歌曲卡片最左边出现圆形勾选框（26px，未选中是 2px `--rule` 圆圈；选中是 `--accent` 实心 + `--on-accent` 白色对勾）

### 5.11 设置页（2026-10-27 新增，M3.11）

- 整页，不是弹窗：首页右上角齿轮图标（44px 图标按钮，`aria-label="设置"`）进入，和歌曲页一样从右边滑入；顶部栏左边返回按钮、标题「设置」

## 6. 动画

所有动画都用这几个时长和曲线：
```css
--dur-fast: 120ms;   /* 按下反馈 */
--dur: 220ms;        /* 一般过渡 */
--dur-slow: 320ms;   /* 页面切换、弹出层 */
--ease: cubic-bezier(.2, .8, .2, 1);
```

| 场景 | 效果 |
|---|---|
| 进入下一个页面 | 新页面从右边滑入（从 30% 位置到 0），同时淡入；旧页面往左移一点并变暗。`--dur-slow`。**每个页面从一开始就是不透明的 `--bg` 底色**，滑入时不能透出下面的页面。变暗用一层半透明遮罩做（不用 `filter`，iPhone 上 `filter` 每一帧都要重画，会卡）。这层是**旧页面自己里面**的 `::after`（`--nav-dim`，10% 黑），只在切页的 320ms 里出现，不是 5.6 说的弹出层暗幕，保留 |
| 浮动播放条（2026-10-27） | 页面滑入之后，播放条从下方往上滑入并淡入，`--dur-slow` + `--ease`，带一点回弹；返回时**没有消失动画**（2026-10-28 开发者决定），播放条跟着切页直接隐藏。歌曲页、编辑歌曲页、打轴页的底部播放条都一样。减弱动态效果时只淡入淡出 |
| 换一组声调字（图标） | 「换一组」的刷新图标转一圈，400ms；开了"减弱动态效果"就不转 |
| 返回 | 反过来 |
| 底部弹出层 | 从下面滑上来，后面不变暗。`--dur-slow` |
| 下拉菜单 | 从「⋯」按钮的位置（右上角）由 0.92 倍缩放到 1 倍并淡入，180ms + `--ease`；关闭反过来。减弱动态效果时只淡入淡出 |
| 当前歌词换句 | 新的当前句：白卡片和紫色描边淡入，字号过渡到 26px；歌词平滑滚动到中间。`--dur` |
| 学词卡片：下一个词 | 旧卡片往左滑出并淡出，新卡片从右边滑入。`--dur` |
| 进度条前进 | 格子颜色过渡。`--dur` |
| 完成页 | 勾选图标从 0.6 倍放大到 1 倍，带一点回弹 |
| 换一组声调字 | 键帽依次淡出淡入 |
| 按钮按下 | 见 5.1、5.2。`--dur-fast` |

**系统开了"减弱动态效果"时**（`@media (prefers-reduced-motion: reduce)`）：去掉所有位移和缩放，只保留淡入淡出，或者直接切换。

## 7. iPhone 适配（开发者用 iPhone 17 Pro Max）

### 7.1 `<head>` 里要有

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
<meta name="theme-color" content="#F7F6FB" media="(prefers-color-scheme: light)">
<meta name="theme-color" content="#15131F" media="(prefers-color-scheme: dark)">
<meta name="apple-mobile-web-app-capable" content="yes">
<meta name="apple-mobile-web-app-status-bar-style" content="default">
<meta name="apple-mobile-web-app-title" content="唱学粤语">
```

### 7.2 安全区
- 顶部栏的上边距、底部按钮和播放条的下边距，都要加 `env(safe-area-inset-top)` / `env(safe-area-inset-bottom)`
- 横屏时左右也要加 `env(safe-area-inset-left/right)`

### 7.3 顶部模糊的问题
开发者反馈：打开一首歌时，屏幕最上面有一小条被模糊。可能的原因有两个：
1. 旧版顶部栏用了半透明背景加 `backdrop-filter: blur`
2. iOS 新版 Safari 会在状态栏下方自己加一层模糊过渡

处理：
- **顶部栏改成不透明**（`--bg` 底色），去掉 `backdrop-filter`
- 加上 7.1 的 `theme-color`，让 Safari 的顶部颜色和页面一致
- 添加到主屏幕后打开（独立模式），Safari 的界面不会出现
- 做完后让开发者在 Safari 和主屏幕两种方式下都截图对比

### 7.4 其他 iPhone 细节
- **状态栏（2026-10-27 第二次）**：iOS 26 Safari 不再读 `theme-color`，而是用靠近屏幕顶部的 fixed 元素的背景色给状态栏上色（WebKit bug 301756）。试过的方案：**a** 页面最上面一条永久的 fixed 色带 `#topTint`（高度 = 顶部安全区，至少 2px；颜色 `--bg`；层级 45，高于遮罩 40）——真机还闪，但色带保留；**b** 遮罩不用 fixed，改成 `position: absolute` 从页面顶部铺到底部，高度在打开弹层时按整页高度算——不闪暗了，但开始闪白（页面变暗而状态栏不变）；**c（当前，最终选定）** 在 b 的基础上遮罩改成完全透明，弹层用 `--shadow-sheet` 阴影 + 描边和页面分开——不闪了，但开发者觉得太素；c + **下半屏渐变变暗**——开发者不喜欢；**d** 回到整屏变暗（fixed、盖住状态栏），但遮罩的 opacity 一直是 1，过渡的是它的背景色（透明 → `--scrim`，`--dur-slow`）；`#topTint` 放到遮罩下面（层级 39），跟着一起变暗——真机打开时闪白、关闭时闪暗，说明 Safari 取色根本不跟过渡动画走；**e** 在 d 的基础上去掉遮罩的过渡：打开时遮罩一下子变成 `--scrim`，关闭时遮罩立刻隐藏（弹层照样滑入滑出）——首页真机打开同步了，关闭时状态栏晚恢复 0.几秒（关闭时换一条新的 `#topTint` 也没用，已撤掉）；**e + 顶栏** 歌曲页等有吸顶顶栏 `.bar` 的页面，Safari 拿顶栏的背景色染状态栏，遮罩盖着也没用，所以弹层打开时 `.bar` 的 background-color 变透明、底色改用 `linear-gradient(var(--bg),var(--bg))` 背景图画（看起来不变），让 Safari 跳过它——关闭时晚 0.几秒的问题还在。2026-10-27 开发者决定回到方案 c（完全不闪，也不变暗），代码恢复成 M3.4 的样子——但从主屏幕图标打开时还会闪。**M3.11（当前）换思路，不再调遮罩**：规则是**顶部附近不能出现有颜色的 fixed 元素**。去掉 `#topTint`；备份改成整页「设置」，不再用弹窗；其他弹窗（词卡、「⋯」菜单、删除确认、未保存提示等）的 `--scrim` 暗色层在打开时放进当前页面的 `<section>` 里，absolute 铺满整页、跟着页面，和弹窗同步淡入淡出。真机结果：不闪了，但状态栏那一条不会变暗，和下面变暗的页面不协调（状态栏由 Safari 自己画）。**M3.12（2026-10-28，最终）整个 App 不再使用暗幕**：底部弹窗只靠 `--shadow-sheet` 阴影浮在页面上，「⋯」改成下拉小菜单（放在吸顶顶栏里，absolute），见 5.6、5.9
- ~~**状态栏那一条**（2026-10-27 第一次，没解决）~~（已作废，被上一条取代，留着只是记录）：弹出层的遮罩不盖住顶部安全区（`top: env(safe-area-inset-top)`），状态栏那一条始终是 `--bg`，`theme-color` 也不变。否则 iPhone 会按遮罩的颜色给状态栏上色，打开/关闭弹层时会闪一下
- **输入框字号至少 16px**。iOS 在输入框字号小于 16px 时，点进去会自动放大整个页面（旧版歌词输入框是 13px，会触发这个问题）
- 所有可点元素加 `touch-action: manipulation`，避免双击放大，也去掉点击延迟
- `-webkit-tap-highlight-color: transparent`，去掉点击时的灰色闪块（因为我们有自己的按下效果）
- 整屏高度用 `100dvh`，不用 `100vh`
- `overscroll-behavior-y: contain` 用在弹出层和歌词列表上，避免拖动时整个页面跟着弹
- iPhone 网页**不能调用震动**（`navigator.vibrate` 在 iOS 上不可用），所以触感反馈只能靠视觉

## 8. 手势：右滑返回

> **2026-10-27 更新（M2 验收）**：开发者的 iPhone 在主屏幕模式下也有系统自带的右滑返回。App 自己实现的右滑会和系统的同时触发，出现两个首页。所以下面第 2 条**不再实现**，两种模式都只用系统右滑；第 1、3 条保留。

**现在的问题**：App 只有一个网页，没有浏览历史。在 Safari 里从屏幕左边缘右滑，会触发浏览器后退，直接离开 App。

**做法**：
1. **每进入一个页面，就用 `history.pushState` 记一条历史**（比如 `{view: "player", songId: "abc"}`）。监听 `popstate`，根据记录显示对应页面，并播放"返回"动画。这样在 Safari 里右滑，就是回到 App 的上一页。顶部的返回按钮也调用 `history.back()`，保持一致
2. **添加到主屏幕后**（`window.matchMedia('(display-mode: standalone)').matches` 或 `navigator.standalone`），iPhone 不提供系统右滑返回，需要自己做：
   - 只在**从屏幕左边缘 24px 以内开始**的横向拖动时触发
   - 当前页面跟着手指往右移动，下面露出上一页（变暗）
   - 松手时：拖过屏幕宽度的 35%，或者速度够快，就完成返回；否则弹回原位
   - 首页不响应
3. 学习流程里（学词、整句）右滑返回，等于点左上角的关闭：回到首页，已完成的句子和已学会的词都已经保存
