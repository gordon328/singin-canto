# 用户数据兼容规则（铁律）

更新 App **绝不能**让用户已有的数据失效或丢失。包括：歌曲、歌词和时间轴、词汇包、改过的读音、生词卡片和复习进度、学习进度、打卡记录、休息卡、已解锁的皮肤、设置、兑换记录。

每次改动涉及数据时，都必须遵守下面 7 条。

## 1. 数据格式版本号 dataVersion

- 本机数据的格式版本记在 IndexedDB 的 meta 表里：`{key: "dataVersion", v: 4}`（和 IndexedDB 自己的版本号无关）
- 每次改数据结构：`data.js` 里的 `DATA.VERSION` 加一，并在 `DATA.STEPS` 里写一个「从上一版升到这一版」的迁移函数
- 迁移按顺序一步一步走（1→2→3→4…），从任何旧版本都能升到最新
- 迁移函数是纯函数：输入输出都是 `{songs, cards, meta, prefs}`（歌曲不带音频；prefs 是 localStorage `yc-prefs`，备份文件里没有，是 null）。不能改动传进来的对象
- 迁移函数要能重复执行（已经升过的数据再跑一遍不变）。v0.30 以前的设备没记 dataVersion，会按第 2 版从头升级
- 已有的版本：

| dataVersion | 哪个版本 | 变化 |
|---|---|---|
| 1 | 第一阶段 | 只有歌曲（songs 表） |
| 2 | M1（2026-10-27） | 加生词卡片 cards 表、杂项 meta 表 |
| 3 | M4a（2026-10-28） | 「每天新学几句」从 prefs.goal 搬到 meta daily；歌曲加学习进度 progress |
| 4 | v0.26（2026-10-30） | meta 加打卡记录 checkin（含休息卡） |

## 2. 只加不删

- 新功能只能**新增字段、新增数据表**，并给旧数据设好默认值（读的时候缺了就用默认值，比如 `STUDY.progressOf`、`CHECKIN.normalize`）
- 不能删除、改名或改变已有字段的含义。要「搬家」时旧字段也留着（比如 prefs.goal 搬到 meta daily 后，prefs.goal 不删）
- IndexedDB 升级只能新增表，不能删除或清空有数据的表
- 数据库打开时不写死版本号（`DB.open()`：先按现有版本打开，缺表才加一补上），这样回退到 v0.30 以后的旧代码也能打开

## 3. 迁移前快照

- 需要迁移时，先把所有数据（不含音频）复制一份存进 `snapshot` 表（只有一条 `key: "last"`，只保留最近一次），再迁移
- 快照内容：`{key, at, from, to, app, data: {songs, cards, meta, prefs}}`
- 迁移结果用一个事务写回（要么全写进去，要么一条都不写）。迁移失败时自动把快照写回、dataVersion 留在旧版，并提示「已经恢复到更新前的数据」
- 设置页「备份与恢复」里有快照时显示「恢复到更新前的数据」：快照里有的记录换回快照的，更新后新加的歌和生词保留；然后 App 重新打开，按当时的迁移规则再升级一次（如果迁移有 bug，修好后上线，再点这个按钮就能用修好的规则重新升级）
- 快照存不进去（空间不够）就不迁移，提示用户

## 4. 备份文件兼容

- 备份文件（格式 v3 起）记着 `dataVersion` 和 `appVersion`
- 导入时，任何旧版本的备份都要能导入：先用 `DATA.upgradeBackup` 升到最新格式，再和本机数据合并
- 旧备份没有 dataVersion：`v: 1` 算第 1 版，`v: 2` 算第 2 版
- 导入比当前 App 更新的备份（dataVersion 比 `DATA.VERSION` 大）：提示「这个备份来自更新的版本，请先更新 App」，不导入
- 只属于这台设备的 meta（`backup` 上次备份时间、`dataVersion`）不放进备份，恢复时也不覆盖

## 5. 兼容性测试（每次上线前必须通过）

- `tests/fixtures/` 里每一种历史数据格式（`data-v1.json` …）和备份格式（`backup-*.json`）各有一份示例数据。**只用编的歌名和句子，不要用真实歌词**
- `node --test`（`tests/data.test.js`）：每一份升到最新后数据完整、数量一致；每一版都要有示例数据，没有就测试失败
- `node tests/browser/run.js data`：在真的浏览器里按旧版本的样子建数据库，打开 App，检查升级、快照、恢复快照、升级失败自动恢复、每一种旧备份导入、太新的备份不导入
- 以后每次改数据结构，都要新增一份对应的 `data-vN.json`（和新格式的备份示例）

## 6. 持久存储

- App 启动时调用 `navigator.storage.persist()` 申请持久存储
- 设置页「备份与恢复」下面有一行小字：「建议从主屏幕图标打开 App，并定期导出备份」

## 7. 删除功能也保留数据

- 以后删除某个功能或皮肤时，对应的数据也要保留
- 比如某个皮肤以后被移除：已解锁记录保留，正在使用的自动切回默认皮肤

## 回退版本时

- 开发者说「回到某个版本」时，如果中间有 CHANGELOG 里标了「⚠️ 数据结构有变化」的版本，先停下来说明风险，让开发者先导出备份再商量
- 特别注意：v0.29 及更早的代码打开数据库时写死了版本号 2，而 v0.30 起数据库是版本 3。回退到 v0.29 或更早，App 会打不开数据库（看起来像数据没了，其实还在）
