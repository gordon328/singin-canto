# M3 验收反馈 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修掉 M3 验收发现的 6 个 bug，做 3 个改进，加「编辑歌曲」和「首页多选删除 + 撤销」两个新功能。

**Architecture:** 仍然是 `index.html` + 几个纯函数 js。编辑歌曲的行操作（插入/拆开/合并/删除）和行号重映射写成 `proof.js` 里的纯函数，Node 单元测试覆盖；页面部分用 `tests/browser/` 的无界面 Chrome 场景测试。

**Tech Stack:** 原生 HTML/CSS/JS，IndexedDB，`node --test`，Chrome CDP。

**Spec:** `docs/第二三阶段开发规格.md` 7.1（第 5–8 条）、7.4、7.5、M3.1；`docs/设计规范.md` 2.1/2.2 `--danger`、5.1 按下状态、6 动画、7.4 状态栏。

## Global Constraints

- 不把任何歌词或音频提交到仓库；测试数据只用编的句子
- 组件里只用 CSS 变量；`--danger` 浅色 `#C2413A`、深色 `#FF8A80`
- 按钮至少 44px 高；输入框字号 16px
- `:hover` 只能写在 `@media (hover: hover)` 里
- 开了"减弱动态效果"：不位移、不缩放、不旋转
- 改了 `sw.js` 缓存的文件内容后 `VERSION` 加一（v4 → v5）
- 数据库结构不变（版本 2）

## Review Focus

1. 编辑歌曲里连着做多次插入/拆开/合并/删除，再保存：learned、overrides、卡片 sources 的行号必须和最终歌词对得上
2. 删除歌曲后 5 秒内离开首页、切后台、再导入新歌：歌要真的删掉，卡片出处要去掉，不能删错别的歌
3. 撤销后再删除同一首歌、或者删除过程中又打开另一首歌
4. 编辑歌曲时换了音频但不保存：播放页要回到原来的音频
5. 选择模式下点返回/右滑、或者没有歌时：不能卡在选择模式

### Task 6: 编辑歌曲的行操作纯函数（新功能 11 的数据部分）

**Files:** Modify `proof.js`；Test: `tests/proof.test.js`

**Interfaces — Produces（Task 7 用）:**
- `PROOF.toEdit(lines, overrides, learned)`：`lines` 的文字已套用 fix。返回 `[{t,end,text,orig,ov:{ci:jp},learned:bool,srcs:[原行号]}]`
- `PROOF.insertAfter(L, i) → L'`：新句 `{text:"",orig:"",ov:{},learned:false,srcs:[]}`，`t = r2((L[i].t + next)/2)`，`next = L[i+1]?.t ?? L[i].end`；新句 `end = next`，`L[i].end = t`
- `PROOF.split(L, i, cut) → L' | null`：`cut` 是字（码点）位置；两边去掉空格后有一边为空 → `null`。第二句 `t = r2((L[i].t + L[i].end)/2)`；两句都继承 `learned`；原句没改过文字时 `ov` 按位置分开（第二句的字序号减去切点和去掉的前导空格），改过就 `{}`；第一句 `srcs` 保留，第二句 `srcs: []`
- `PROOF.mergeUp(L, i) → L'`（i>0）：文字 `a + " " + b`，`t` 取上一句、`end` 取这句；`learned = a.learned && b.learned`；没改过文字的那一半保留 `ov`（第二句字序号 + `[...a.text].length + 1`），`orig` = 合并后的文字；`srcs` 合并
- `PROOF.remove(L, i) → L'`：上一句 `end` = 被删句的 `end`
- `PROOF.toSong(L) → {lines:[{t,end,text}], overrides:{"li:ci":jp}, learned:[li], map:{原行号:新行号}}`：按 `t` 稳定排序；文字去首尾空格；`text !== orig` 的句子不带 `ov`；结束时间不晚于下一句开始、不早于自己开始
- 删掉 `PROOF.clearLineOverrides`（被 `toSong` 取代）

- [ ] 写测试：插入时间取中间、最后一句插入；拆开位置、learned 继承、ov 分开、光标在头尾返回 null、改过文字后拆开 ov 清空；合并文字/时间/ov 挪位/learned 规则；删除后上一句 end；连做 插入→拆开→合并→删除 后 `toSong` 的 overrides、learned、map 都对；排序；不修改传入的数组

## 执行结果（2026-10-27）

- 9 个任务全部完成；`node --test` 56/56，`node tests/browser/run.js` 184/184
- 压力测试：进出歌曲页 30 次，事件监听 58→58、页面元素 1154→1154、每轮耗时不变，没有累积。改了两处可能导致卡顿的地方：切页变暗不用 `filter`、回首页放开音频
- 审查（opus）：无严重问题；3 个重要问题已修（合并到空句时读音错位、撤销期间恢复备份会丢歌、离开编辑页后新音频仍被装上）

**我做的决定：**
- 本机 Chrome 不能模拟安全区，状态栏遮罩只检查了样式，真机效果靠 iPhone 验收
- 代码里本来没有 `:hover`；卡住的是 `:active`，用 `body.settling` 在切页后关掉按下效果，下一次手指按下再打开，顺带取消焦点
- 导入页：音频选了但还在读取时，提示"音频还在读取，稍等一下"
- 合并：两句都学会才算学会（其中一句是空的就跟着有字的那句）；拆开：两句都继承；删除：指向这句的卡片出处去掉
- 拆开后展开第二句，合并后展开合并的那句，删除后全部收起
- 歌曲页单首删除也显示「已删除 1 首歌 · 撤销」
- 「删除（0）」不灰掉，点了提示

**留到以后的小问题：**
- 打开新弹层时不会结束还挂着的删除确认（目前所有出口都会关弹层，没有实际影响）
- 导入页防重复保存是 1.5 秒计时；打轴页「完成并保存」连点可能存两次（旧代码）
- App 被直接关掉时，还在撤销期的删除可能没写完（切后台时会先删，一般没事）
- 输入框外面的浅阴影被剪掉；词汇包、备份的输入框也变成 7 行高
- 用前进手势离开首页不会退出选择模式
- 撤销期间导出备份，卡片出处还带着已删的歌
- 编辑页顶部小字的歌名不随输入实时更新
