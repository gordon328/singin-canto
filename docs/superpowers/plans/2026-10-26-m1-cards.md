# M1 · 数据库升级 + 卡片基础 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** IndexedDB 升到 v2（新增 `cards`、`meta` 表，旧歌不丢）；新建纯函数文件 `srs.js`（复习算法 + 卡片工具）并配测试；备份升到 v2（含卡片）；自由听词卡里加「＋ 加入生词」。

**Tech Stack:** 原生 JS、IndexedDB、Node 24 自带的 `node:test`（只用来跑测试，不是构建工具）。

**Spec:** `docs/第二三阶段开发规格.md` v2（第 3.1、3.2、3.5、6.2、6.4 节，第 9 节 M1）。同时遵守 `CLAUDE.md`。

### Task 2：卡片工具 `newCard` / `dueLabel` / `mergeCards`

**Files:**
- Modify: `srs.js`（追加三个函数，加进导出对象）
- Modify: `tests/srs.test.js`

**Interfaces:**
- Consumes: `SRS.newSrs`
- Produces:
  - `SRS.newCard({w, jp, zh, tip, oral}, source: {songId, li} | null, now) -> Card`：结构见规格 3.2。`sources` 在 source 为 null 时是 `[]`；`known: false`；`srs: newSrs(now)`；`created = updated = now`；`zh`、`tip` 缺省为 `""`；`oral` 转成布尔值
  - `SRS.dueLabel(due, now) -> string`：按"凌晨 4 点换日"的日子算相差几天：`<= 0` 返回 `"今天"`，`1` 返回 `"明天"`，其他返回 `"N 天后"`。算法：`dayKey(t)` = 把 `t - 4 小时` 取本地日期的零点；天数 = `Math.round((dayKey(due) - dayKey(now)) / DAY)`
  - `SRS.mergeCards(local: Card[], incoming: any, now) -> Card[]`：按 `w` 合并。`incoming` 不是数组时，返回 `local` 的副本。incoming 里每一项先规范化：`w` 不是非空字符串就跳过；`srs` 缺失或 `due` 不是数字时换成 `newSrs(now)`；`sources` 不是数组时换成 `[]`，并滤掉没有 `songId` 的项；缺 `updated` 当作 0。两张卡冲突时，`srs.reps` 大的胜出；reps 相同时 `updated` 新的胜出；都相同保留本机的。结果的 `sources` 取两边并集，按 `songId + ":" + li` 去重
